# 用户管理

## 状态

开发中

## 子菜单

### 用户账号

- 查询：按用户名、邮箱和状态分页查询。
- 详情：查看账号 ID、用户名、邮箱、权限组、状态和最后登录信息。
- 编辑：修改邮箱等账号资料。
- 注册账号：创建游戏账号并按服务端密码配置写入。
- 重置密码：设置新密码并记录审计日志。
- 封禁/解禁：切换账号状态并记录审计日志。

### 游戏角色

- 查询指定玩家的角色、等级、职业和在线状态。
- 在角色列表打开详情抽屉，查看成长、属性、生命/魔力、位置和在线状态。
- 成长调整设置基础等级、职业等级和职业 ID；职业等级 `job_level` 与职业 `class` 分开传递。
- 属性管理允许调整 STR、AGI、VIT、INT、DEX、LUK 等基础属性，并提供恢复 HP/SP 和重置属性操作。
- 技能管理提供“重置技能”，由游戏服务清除已学习技能并按 rAthena 规则返还技能点。
- ATK、DEF、最大 HP 等派生属性只展示计算结果，不作为普通持久化字段直接修改。
- 变更职业会影响等级上限、技能树和角色表现，当前由同一维护弹窗提交，但仍由 map-server 独立执行职业变更逻辑。

### 登录日志

- 查询玩家登录时间、IP、结果和失败原因。
- 查看单条登录记录；删除和导出按钮暂不提供。

## 角色维护设计

- 角色数据库是查询来源，不是后台直接修改在线角色的写入口。
- 等级、职业、属性和技能变更统一通过私有 Game Control API 交给 map-server 主线程执行，由游戏服务校验范围、重新计算状态并保存角色。
- Game Control API 只接受结构化、白名单化的业务命令，禁止执行任意 SQL、任意控制台命令或任意 GM 指令。
- 当前入口复用命令提交与执行 Service，并通过可注入的 `GameServer` Contract 与游戏服务通信；后续再按业务语义拆分角色维护 Service。
- 操作包含目标角色和幂等键，并记录操作者、请求、服务端响应和最终状态。
- 在线角色不得通过后台直接更新 `char`、`skill` 等表，避免 map-server 后续保存内存状态时覆盖后台修改。

目标接口按业务语义拆分；当前只读详情接口已完成，写操作暂由受权限保护的通用结构化命令入口承载：

- `GET /api/players/characters/{charId}`：角色详情。
- `PATCH /api/players/characters/{charId}/progression`：调整等级和经验。
- `PATCH /api/players/characters/{charId}/stats`：调整基础属性。
- `POST /api/players/characters/{charId}/stats/reset`：重置基础属性。
- `POST /api/players/characters/{charId}/skills/reset`：重置技能。
- `POST /api/players/characters/{charId}/vitals/restore`：恢复 HP/SP。

权限不复用宽泛的 `players.edit`，计划拆分为查看角色、调整成长、调整属性、重置技能和恢复状态等权限。
