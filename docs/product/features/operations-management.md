# 运营管理

## 状态

开发中

## 子菜单

### 发放物品

- 保留现有邮件发放能力，使用服务端物品集合校验可发放物品。
- 直接发放背包必须等 Game Control API 支持后实现，禁止直接写在线角色背包表。

### 魔物召唤

- 默认选择一个在线角色，并在该角色附近的合法格子生成魔物。
- 魔物支持按 ID、中文名和英文名搜索，并展示图鉴中的本地图片和关键属性。
- 输入数量、生成半径和自动清理时间。
- 魔物图鉴详情提供“召唤”快捷入口，但实际执行仍属于运营管理用例。

后台管理员没有天然的游戏坐标，因此“管理员附近”统一解释为“所选在线测试角色附近”。map-server 负责读取角色实时位置并寻找合法格子，后台不要求管理员填写地图和坐标。后续可以为后台账号配置默认测试角色，但不能依赖这一绑定才能执行召唤。精确坐标生成不属于当前需求，确有必要时再作为独立的高级测试能力设计。

## 实现方案

- 魔物召唤是 map-server 的运行时操作，不写玩家数据库或 `happyro_admin` 资料表。
- Laravel 当前复用命令提交、持久化和执行 Service，通过可 Mock 的 `GameServerGateway` 调用私有 Game Control API。
- Game Control API 解析目标角色的实时位置，检查角色在线、地图已加载、附近存在可行走格子、魔物 ID、数量上限和清理时间。
- 默认使用一次性生成，不建立永久刷新点；需要永久刷新时必须作为另一项配置功能单独设计。
- 接口只接受结构化的 `monster.spawn` 命令，不暴露 rAthena 任意脚本或控制台执行能力。
- 每个请求使用幂等键，防止网络重试造成重复生成；后台保存请求状态和游戏服务返回的实体标识。

目标业务语义接口：

- `GET /api/operations/monster-spawn-targets`：搜索在线目标角色。
- `POST /api/operations/monster-spawns`：提交召唤请求。
- `GET /api/operations/monster-spawns/{operationId}`：查询执行结果。

当前使用 `operations.game-control` 权限；后续拆分 `operations.monster-spawn`，与 `operations.item-grant` 分离。命令记录保存操作者、魔物、数量、目标角色、服务端返回结果和最终状态。

## 实现记录

- 已实现邮件发放物品。
- 已建立 `monster.spawn` 结构化命令、命令状态机、幂等持久化和可 Mock 的 Game Server Gateway 契约。
- 已完成后台到服务端的 HTTP Gateway，并通过 Unix Socket 将命令交给 map-server 主线程执行。
- 服务端能力列表按实际注册表返回；召唤命令会校验在线目标、合法格子、数量、半径和自动清理时间。
- 已通过启用控制通道的真实 map-server 和在线 Robrowser 角色验收召唤及自动清理。

角色维护入口位于 `players/characters` 列表的操作列，需要同时拥有 `players.view` 和 `operations.game-control` 权限。弹窗统一提交结构化命令，当前支持等级/职业、基础属性、技能点重置和状态恢复；角色必须在线，命令由 map-server 主线程执行。
